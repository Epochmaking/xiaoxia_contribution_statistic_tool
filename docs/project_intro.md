# 小夏公众号贡献统计工具 —— 项目介绍（面试版）

> 一个用 AI 辅助开发的实用小工具，解决团队每月统计公众号稿费的重复劳动。

---

## 一、项目背景

团队运营一个微信公众号「小夏」，每月要统计每篇文章的**参与人员**（文、排版、校对等）和**阅读/点赞数据**来算稿费。之前都是人工逐篇打开文章、复制落款、手填 Excel，一个月几十篇要花好几个小时，还容易抄错。

所以想做个桌面工具，把这事自动化掉。

---

## 二、功能流程

工具按四步走，对应 GUI 上的四个步骤页：

```
步骤一：获取公众号标识（BIZ）
   ↓  开系统代理，用户在微信里打开公众号，工具自动抓到 BIZ
步骤二：抓取当月文章列表
   ↓  抓到分页接口模板后自动循环翻页，按月份过滤
步骤三：逐篇爬取文章内容 + 数据 + 落款
   ↓  浏览器自动打开每篇文章，LLM 提取落款角色
步骤四：展示结果 + 算稿费 + 导出 Excel
```

---

## 三、技术选型

都是 Python 生态里比较成熟的方案，主要是图省事：

| 用途 | 选的工具 | 原因 |
|---|---|---|
| 桌面界面 | PySide6 + Qt Designer | 拖拽画界面，信号槽好用来做异步 |
| 抓微信接口 | mitmproxy | 直接构造请求会被微信签名拦住，用代理抓一次合法请求再改参数重放就行 |
| 打开文章页 | Playwright | 比 Selenium 稳，能控制窗口显隐 |
| 存数据 | SQLite + SQLAlchemy | 本地临时存一下，不用装数据库 |
| 提取落款 | 智谱 GLM API | 中文理解好，能直接返回 JSON |
| 打包 | Nuitka | 编成 exe，同事不用装 Python |

---

## 四、主要实现思路

### 4.1 怎么绕过微信接口签名

微信公众号的分页接口带签名参数，自己拼请求会被拒。

做法很直接：开 mitmproxy 代理，让用户在微信里打开一次公众号历史消息页，工具**抓到这次合法请求当模板**，之后只改 `offset`（页码）参数，原样重放。签名、cookie 都带着，接口就认。

```python
# 大致思路（controllers/crawler.py）
new_flow = template_flow.copy()          # 复制抓到的请求
new_flow.request.query["offset"] = str(offset)   # 只改分页参数
master.commands.call("replay.client", [new_flow])  # 重放
```

### 4.2 人机验证怎么处理

微信偶尔会弹人机验证页。无头浏览器更容易被拦，所以用 headed 模式，但启动时把窗口移到屏幕外（用户看不到）。检测到验证页了，再把窗口弹出来让用户手动过一下，过完继续跑。

检测方式很简单：URL 里带 `captcha` 关键词，或者页面文字出现"环境异常""人机验证"。

### 4.3 落款提取用 LLM 分两步

文末落款格式不固定，比如：

> 文：张三、李四  排版：王五  校对：赵六

直接让 LLM 一次输出 JSON 容易混进正文，所以拆成两步：

1. **第一步**：只从文章末尾 300 字里把落款那块原文提取出来（纯文本）；
2. **第二步**：再把这段文本转成结构化 JSON，比如 `{"文": ["张三","李四"], "排版": ["王五"]}`。

用 `response_format=json_object` 保证输出格式对，失败了自动换备用模型重试。

### 4.4 爬得慢怎么办

一篇文章要开浏览器等几秒，再调 LLM 又要几秒，串行跑几十篇太慢。

简单做了个流水线：浏览器爬完一篇就丢队列，后面几个线程同时调 LLM 解析落款，再几个线程同时做结构化和写库。浏览器是单线程（怕被反爬），LLM 调用可以多线程并发。整体速度大概快了两三倍。

```
浏览器(单线程) → 队列 → LLM解析(多线程) → 队列 → LLM结构化+写库(多线程)
```

### 4.5 界面不卡

耗时操作都放 QThread 里跑，通过信号槽把结果回传主线程更新界面。人机验证时爬虫线程阻塞等待，用户点完按钮再唤醒它。

---

## 五、数据存哪

用 SQLite，数据库文件放系统临时目录，**每次启动重建**，跑完就没了，不留用户数据。

主要就是一张 Article 表，存标题、链接、发布时间、阅读量、点赞数、原始落款文本、结构化后的落款 JSON。算稿费时把 JSON 里的人名展开，按每人参与几篇 × 稿费基数算。

---

## 六、打包

Nuitka 编成独立目录，带上 PySide6 和 Playwright 的浏览器文件，同事直接双击 exe 就能用。主要踩了个坑：浏览器二进制的路径打包前后不一致，后来在 build 脚本里加了目录探测，优先用系统装的，没有就用项目里备份的。

---

## 七、AI 辅助开发过程

这个项目是用 AI 辅助写的（vibecoding），大致流程是：

1. **先跟 AI 聊清楚要做什么**：把四步流程、微信签名、落款格式这些需求讲清楚，让 AI 给技术选型建议；
2. **让 AI 出整体框架**：目录结构、模块划分、每个文件大概放什么，AI 给初稿，我调整；
3. **分模块让 AI 写代码**：比如让 AI 写 mitmproxy 抓包重放的逻辑、Playwright 打开文章的逻辑、LLM 调用的函数，写好我跑一下调一调；
4. **遇到问题一起调**：比如代理退出后没清理导致上不了网、人机验证时线程卡死、打包后浏览器找不到，这些把报错丢给 AI，它给方向，我来验证改对不对；
5. **Prompt 和细节自己把关**：LLM 提取落款的 Prompt 是我反复测了好多篇文章调出来的，AI 写的第一版容易混进正文，得自己加规则。

整体感觉是：常规代码 AI 写得很快，但**跟业务强相关的部分（比如微信接口怎么绕、落款怎么提、打包路径怎么对）还是得自己想清楚**，AI 给的方案要跑通验证才能用。

---

## 八、项目收获

- 熟悉了用 mitmproxy 抓包重放的思路，知道怎么绕过签名类接口；
- 练了 PySide6 桌面开发和多线程异步的基本用法；
- 体会了 LLM 落地到真实业务时 Prompt 调优的重要性；
- 积累了用 AI 辅助开发的经验：怎么把问题拆清楚喂给 AI、怎么判断它给的代码靠不靠谱、哪些地方必须自己盯。
